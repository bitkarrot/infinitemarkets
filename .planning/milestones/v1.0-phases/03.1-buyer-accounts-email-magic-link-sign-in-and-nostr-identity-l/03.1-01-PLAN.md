## Phase Goal

**As a** buyer without a Nostr signer, **I want** a per-shop account my orders bind to — reachable by email or Nostr — **so that** my order history follows a verified identity instead of a lost private link; **and as an** existing Nostr buyer, **I want** my sessions and history to keep working unchanged, **so that** the account model is additive, never a migration cliff.

(Story source: Phase 03.1 CONTEXT D-01..D-04; carried buyer-history recovery from Phase-2 UAT.)

<objective>
Lay the account foundation everything else in the phase builds on: the m008 schema (buyer_accounts, email_signin_tokens, rebuilt buyer_sessions, orders.buyer_email_hash, email_queue.payload_enc, nostr_challenges link columns) with in-migration backfill, the `PURPOSE_BUYER_EMAIL` domain, account-scoped session minting with legacy-session compat, the union order history, identity-symmetric claim, verified-email checkout attribution, and the profile endpoint's email-account shape — proven by a Wave-1 runtime suite.

Purpose: every later surface (magic-link sign-in, linking/merge, profile UI) reads and writes through this exact account/session contract; landing it first keeps each following plan a vertical, not a schema negotiation.

Output: `m008_buyer_accounts`, `crypto.PURPOSE_BUYER_EMAIL`, account-aware `nostr_auth`, union `/nostr/orders`, email-hash checkout writes, `test_buyer_accounts.py`.
</objective>
