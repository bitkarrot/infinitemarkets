## Phase Goal

**As a** Nostr buyer, **I want** to sign in with my Nostr key on the storefront and see every past order — including delivery content I paid for — plus claim orders from old private links, **so that** losing my message history never loses my purchases; **and as a** merchant, **I want** a real Messages workspace and honest shop modes, **so that** Nostr conversations, hostile intake, and relay-auth problems are visible and actionable instead of invisible.

(Story source: carried Phase-2 UAT items + REQUIREMENTS.md GAM-03/GAM-04 surface concerns; Phase 3 goal criterion 3's buyer-facing half + CONTEXT D-01..D-28.)

<objective>
Ship every buyer- and merchant-facing surface of the Gamma channel: NIP-07 challenge/session sign-in with revocable cookies, unified order history + inline digital delivery, the claim flow that binds a pubkey to a lost-link order, session-attributed web checkout that receives NIP-17 copies, the four-state storefront mode with its hard invariants, the fifth-nav Messages workspace (folders/unread/reply/compose/delivery evidence/retry/health), the Rejected-intake + mute surface, relay-auth + paid-relay status, and the admin mode panel — plus Playwright coverage.

Purpose: protocol work (03-01/03-02) is worthless to users without these surfaces; the sign-in + claim path is the *only* buyer history-recovery mechanism this phase (D-02).

Output: `nostr_auth.py` buyer half, `storefront_mode.py`, `/nostr/*` public API, Messages + Rejected + relay-auth + mode admin surfaces, `public_nostr.js`, two Wave-0 runtime suites + e2e additions.
</objective>
