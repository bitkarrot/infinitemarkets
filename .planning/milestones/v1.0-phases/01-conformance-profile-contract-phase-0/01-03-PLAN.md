## Phase Goal

**As a** merchant-operator, **I want to** prove the exact LNbits/SDK/platform/database profile with reproducible qualification evidence before any production runtime is built, **so that** merchants' real funds are never exposed to an unqualified contract.

(Story source: REQUIREMENTS.md user story "As an operator, I can prove the exact LNbits/SDK/deployment profile before merchants use real funds", adapted to the Phase 1 qualification-harness boundary.)

<objective>
Build the protocol, relay, auth/privacy, FX, and contract-closure fixtures that complete the conformance profile (workstream 01-03 from the ROADMAP: "Build protocol, relay, auth/privacy, FX, and contract-closure fixtures"): relay ACK classification and NIP-17 wrap validation/routing fixtures with golden + seeded generated cases (P0-04, P0-05), NIP-89 local routing and host auth/privacy/lifecycle probes (P0-11, P0-12), the Decimal/FX boundary model with measured float-boundary error (P0-13), and the contract-closure gate proving no undeclared state, field, route, identifier, or release dependency remains and that P0-01..P0-14 all carry recorded evidence (P0-14).

Purpose: Release A must not ship on unproven relay-ACK semantics, unproven wrap validation, a broken NIP-89 entry point, assumed host auth behavior, or drifting FX math — and the owner cannot approve the pins (D-11) without a closed evidence bundle.

Output: extended harness modules (sdk, relay, nip89, authprobe, fx, registry, evidence report rendering), six p0-named test modules, checked-in golden fixtures for NIP-17/NIP-89/NIP-15 plus a kind-30402 naddr, seeded generated edge cases, PINS.md completion (FX measured bound, protocol namespace pin, approval section), and the final evidence bundle.
