# Milestone v1.0: Core Commerce and Hardening

**Status:** ✅ SHIPPED 2026-10-13
**Phases:** 1–5 (+ inserted 03.1)
**Total Plans:** 24

## Overview

One authoritative commerce system implemented as an LNbits extension: a
merchant sells one inventory safely through LNbits-backed web checkout and
Nostr/Gamma (NIP-17) flows without duplicate invoices, double allocation, or
relay delivery being mistaken for payment truth. The milestone covered
conformance qualification, web commerce, private Gamma orders, buyer
accounts, catalog import/export, and a final hardening pass that repaired
six reopened correctness/recovery findings plus a test-lifecycle defect —
then verified everything against a real deployed host, a real external
client, and a four-profile CI matrix.

## Milestone Summary

**Decimal Phases:**

- Phase 03.1: Buyer accounts (inserted after Phase 3 for email+Nostr
  unified buyer identity)

**Key Decisions:**

- One canonical pricing/inventory/invoice/settlement pipeline shared by web
  and Gamma checkout — Gamma never gets a divergent commerce path (§8.x).
- NIP-17 transport is evidence-only: every wrap is verified, deduplicated,
  and relay-scoped per party; relay delivery is never payment truth.
- Hardening-before-expansion: the 2026-10-11 milestone audit reopened
  Phase 2/3 acceptance on F1–F6 and deferred the live external UAT rather
  than cutting a release on stale green.
- D-33 disposition: §9.5's literal OS/container egress requirement is
  satisfied for Release-B conformance by in-code egress drills + documented
  operator egress responsibility (PINS.md) + gated-relay evidence.
- F1 host-browser errors disposed as an operator-accepted host limitation:
  the pageerrors are upstream LNbits defects (untrusted-cert ServiceWorker
  registration, unguarded `g.wallet.id`) unfixed on upstream `main`.

**Issues Resolved:**

- F1–F6 financial/ordering/recovery defects (merchant-command authority,
  invoice-uncertainty recovery, reservation coverage, revision-bound
  dependencies, no-route claimability, bounded inbox admission) — all
  repaired with permanent regressions on SQLite + PostgreSQL.
- CI-01 test-exit defect (orphaned aiosqlite worker on cancelled engine
  checkout) — root cause demonstrated and fixed.
- Live external-client conformance — real `plebeian.market` order over
  public relays including a discovered client divergence (detail-page
  Add-to-Cart emits `item=30402:<pk>:<event-id>`; registered as known
  delta #7).

**Issues Deferred:**

- S1–S4 (entitlement permanence, identifier/history contract,
  evidence/observability shape, focused SQL/transport cleanup).
- External inventory/shipping integrations, shipping-import expansion,
  reviews, NIP-37, non-manual payment modes, subscriptions/preorders,
  Wasm, buyer unlink/notification-preference expansion.
- WR-01 browser RED chronology — permanent honesty note (retrospective
  capture), operator-accepted.

**Tech Debt / Accepted Limitations:**

- Pinned-host admin pageerrors are upstream LNbits defects — documented,
  not fixed, not filtered (F1 limitation).
- Plebeian detail-page item refs use event-id instead of d-tag — recorded
  as conformance known-delta #7; merchant intake correctly rejects and
  replies `status=rejected` (D-22).
- Merchant kind-0 has no `lud16`; Plebeian's own invoice UI cannot render,
  payment requests flow via the extension's type-2 wrap as designed.
