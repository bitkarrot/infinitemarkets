## Accomplishments

- `nostr_signin` render flag widened to `inbox_state == 'active'` OR (`ext_settings().email_enabled` AND `is_email_notifications_configured()`), gating chip markup + `public_nostr.js` consistently — email-only deployments now get a reachable, honest sign-in affordance.
- Modal offers both D-13 methods: existing NIP-07 round-trip unchanged + `#gm-email-input`/`#gm-email-btn` magic-link request ending on the single `EMAIL_SENT_COPY` literal (no-oracle). Availability arrives via the openModal `/nostr/challenge` probe (`email_signin`/`nostr_signin` flags, optimistic-true defaults); unavailable methods render hints naming the fix. Chip label is method-neutral 'Sign in' and only opens the picker.
- Email-aware account chrome: `/nostr/profile` `{email}` flows into `state.email`; `displayName()` falls back kind-0 → npub short → truncated email; menu id line shows the truncated email when no npub. Claim + prompt copy made method-neutral.
- D-09 note: `renderOrdersPage` reads `gm_bound_orders`, renders 'We found N past order(s) linked to your account.' once, then removes the item.
- Profile page (D-12): 'Sign-in methods' card (email/npub rows + 'linked' pills + display-only order-prefs note), 'Link a Nostr key' card (link challenge → window.nostr → `/nostr/link/verify`, honest 409 copy, merged/linked confirmations), symmetric 'Link an email' card (`/nostr/link/email`, uniform copy), kind-0 editor gated on `state.npub` with a locked card for email-only accounts.
- E2E harness: dummy `LNBITS_EMAIL_NOTIFICATIONS_*` env flips `is_email_notifications_configured()` on; `GET /_e2e/mailbox?to=` decrypts the newest `channel='account'` row and returns the fragment link; `/_e2e/sign` accepts a `label` for fresh-key scenarios.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] Modal re-render wiped the typed email/nsec input**
- **Found during:** Task 3 (first e2e run — 'email account links a Nostr key' spec flaked to 'Enter your email address.')
- **Issue:** `openModal`'s async capability-flag probe calls `renderModal()` on arrival; a buyer typing while the probe is in flight loses their input because the rebuild recreates the DOM.
- **Fix:** `renderModal` now captures `gm-email-input`/`gm-nsec-input` values before `GM.clear` and restores them into the rebuilt inputs.
- **Files modified:** `infinitemarkets/static/infinitemarkets/js/public_nostr.js`
- **Verification:** failing spec passes; full 20/20 e2e green
- **Committed in:** `d22791e` (Task 3 commit)

**2. [Rule 1 — Test setup] Link-nostr e2e scenario hit an honest MERGE_CONFLICT**
- **Found during:** Task 3 (second e2e run — account card never gained the npub row)
- **Issue:** the shared `e2e-buyer` stub key's account already holds a linked email (from the link-email spec), and the email-session account holds its own email — `buyer_accounts` has one `email_hash` column so the union is unrepresentable → correct 409 'already linked elsewhere'. The scenario needed a fresh key, not the shared one.
- **Fix:** `/_e2e/sign` accepts an optional `label` selecting a different `fixed_test_keys` key; `installNostrStub(page, label)` forwards it; the spec uses `'e2e-linker-key'` — an identity with no existing account → clean link.
- **Files modified:** `tools/e2e_server.py`, `tests/e2e/buyer.spec.ts`
- **Verification:** spec passes; merge path remains covered by `tests/runtime/test_email_signin.py#test_union_merge_moves_identity_sessions_orders`
- **Committed in:** `d22791e` (Task 3 commit)
