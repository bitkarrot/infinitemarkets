## Accomplishments

- `m008_buyer_accounts` creates `buyer_accounts` (D-01: nullable `email_hash`/`pubkey_hash`, partial-unique merchant-scoped, `retired_at` never hard-delete) and `email_signin_tokens`; rebuilds `buyer_sessions` for `account_id` + nullable `buyer_pubkey_hash` (SQLite cannot relax NOT NULL — first rebuild in this codebase); adds `orders.buyer_email_hash` + index, `email_queue.payload_enc`, `nostr_challenges.purpose`/`account_id`.
- In-migration backfills: `orders.buyer_email_hash` from decrypted `contact_enc` (malformed rows skipped, row-count-only logging) and one `buyer_accounts` row per distinct session `(merchant_id, pubkey_hash)` with `pubkey_enc` re-encrypted under the account-id AAD. Both helpers are extracted, re-runnable, and resolve `ext_settings()` lazily so env-less `keystore_env` runs stay clean.
- `verify_signin`/`signin_nsec` mint sessions against `buyer_accounts`; `session_from_cookie` returns `{id, merchant_id, account_id, buyer_pubkey, email, pubkey_hash, email_hash, expires_at}` — account row authoritative, `account_id IS NULL` rows resolve identically to before, missing/retired accounts fail closed.
- `/nostr/orders` is the `buyer_pubkey_hash = :ph OR buyer_email_hash = :eh` union (NULL-safe); `/nostr/profile` GET returns `{pubkey, npub, email, profile}` null-safe for email-only accounts; POST refuses with 422 `nostr-identity-required` before any nostr_sdk work.
- `claim_order` binds whichever identities the account offers under per-column CAS — bound-column mismatches are the identical `CLAIM_INVALID`; checkout writes `orders.buyer_email_hash` from the session's verified email (never the unverified form email) on web intake and from the payload email on gamma intake.

## Decisions Made

- **Undecryptable session groups mint no account** (deviation of plan's "one account per distinct pair" for the corrupt-ciphertext edge): minting a pubkey_hash-only account would move those sessions onto the account path where the pubkey can never be read; leaving them on `account_id IS NULL` preserves the legacy path intact. Consistent with the "pre-m008 rows MUST NOT break" prohibition.
- **Account-field decrypts are best-effort** (`_decrypt_account_field`, `_customer_email` posture): a corrupt `email_enc`/`pubkey_enc` degrades the plaintext field to `None`; the hash columns (authoritative for lookups/claims/union) are unaffected.
- **Legacy `session_from_cookie` path unchanged exactly** — `account_id IS NULL` rows still require a decryptable `buyer_pubkey_enc`, returning `None` otherwise.
- **Retired/missing account ⇒ `None` session** per plan (fail closed; merge re-points sessions atomically in plan 02).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] Corrupt-enc session groups skip account creation**
- **Found during:** Task 1 (m008 backfill design)
- **Issue:** Plan's `_backfill_session_accounts` creates an account per distinct `(merchant_id, pubkey_hash)`; with an undecryptable `buyer_pubkey_enc` that account would carry a hash its secret can't back — sessions would join it and then fail on the account read path.
- **Fix:** Try each session row's ciphertext in the group; if none decrypts, mint no account — sessions stay `account_id IS NULL` (legacy path, still resolving).
- **Files modified:** `infinitemarkets/migrations.py`
- **Verification:** `test_m008_rebuild_preserves_and_backfills` seeds a corrupt-enc session and asserts `account_id IS NULL` after rebuild; account count excludes it.
- **Committed in:** `0900f82`

**2. [Rule 2 - Missing critical] Backfill idempotency guards**
- **Found during:** Task 1
- **Issue:** A mid-migration failure would re-run m008; unguarded backfill UPDATEs/INSERTs are wasteful (and the account INSERT would hit the partial-unique index).
- **Fix:** Orders backfill filters `buyer_email_hash IS NULL`; session backfill skips existing `(merchant_id, pubkey_hash)` accounts via SELECT. Both helpers return affected counts and re-run as no-ops.
- **Files modified:** `infinitemarkets/migrations.py`
- **Verification:** `test_m008_rebuild_preserves_and_backfills` re-invokes both helpers and asserts 0/0.
