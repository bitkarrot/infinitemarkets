<tasks>

### Task 1: Freeze-guard lifecycle rehearsal

Using fixed-source nostrmarket fixtures with an authorized merchant wallet and real service/API entrypoints, import stock=1 and one unpaid payable invoice qty=1; old intake active, missing order or unknown status each blocks snapshot. After old-source disable and complete invoice evidence, wait blocks product; partition holds last unit; both web/Gamma order attempts mint no invoice/hold. For stock=2, a buyer can reserve only the surplus unit. Check reviewed category, guarded publication and projected stock. Verified old payment consumes qty once; verified unpaid terminality in a separate case releases once. Cover duplicate notices, late paid after claimed expiry, poll failure, abort with payable hold, completion with partitioned liability, and native-product checkout unaffected.

### Task 2: Real contention on the shared allocation primitive

Use two independent DB connections, product stock_on_hand=1 and shared service-level conditional stock allocation. Coordinate starts **before** write transactions; observe both entrants and attempt results without a barrier behind a held SQLite/PostgreSQL lock. Exactly one legacy partition/new-order reservation succeeds, reserved never exceeds on-hand, and no losing order creates an invoice. This is a primitive-level race, not a browser-level race: policy intentionally blocks a checkout while unpartitioned. Repeat on both supported backends and demonstrate the test catches removal of the capacity guard.

### Task 3: Round-trip/media/visual checks and release evidence

Exercise authenticated export of a product with variants and 20 ordered images, spreadsheet-formula fields, and safe reimport as blocked drafts; 21-image input requires explicit selection. Test media upload content validation, hash mismatch, owner separation, duplicate upload, quota exhaustion, archive traversal/decompression bomb, network fetch prohibition, interrupted retry and no unintended publication. Browser smoke uses the private screenshots as opt-in visual references for 1440×900 and 390×844; no copies of private raw merchant products in git. Run `make lint`, targeted SQLite/PostgreSQL runtime and Playwright suites, and applicable `make verify` checks. Record measured results and limitations in `04-VERIFICATION.md`, and update architecture/technical/operator docs. Only mark LEG-03..06 complete if all gates actually pass; tag/release/deploy is a separate decision.
</tasks>
