Merchant can inspect and execute a file-based import into safe drafts, without assuming the uploaded catalog or optional orders are a complete liability snapshot.

Any imported draft remains blocked from publication and checkout pending 04-02's cutover verification.
</objective>

### Task 1: Contract, m010 schema and immutable upload snapshot

Define exact upload schemas: allowlisted nostrmarket JSON `stalls/products/orders` with nested `order_items` and `invoice_id`, NIP-15 event dump 30017/30018, Shopify CSV (handle/variant/image row grouping, explicit source instance). If orders are absent, **record completeness unknown**, never zero liabilities by default. Retain only normalized allowlisted import rows + HMAC/salted source digests (no raw order/customer data or bytes). Create `catalog_imports` with source hash/state/preview totals, `import_rows`, merchant-scoped CSV presets, `imported_liabilities` with provisional state and encrypted invoice reference if later host verification requires it, plus product source tuple + import marker. Unique index on `(merchant_id, source_kind, source_instance, legacy_id)` (respect NULL handling on SQLite/PostgreSQL). Add m010 to the extension migration registry and runtime DB fixtures; cover forward migration on both dialects.

### Task 2: Parse, validate, dry-run and execute safely

Limit request body before parsing (≤10 MB), rows (≤5000), nesting, field lengths and CSV columns; reject key-like fields and unknown sensitive fields. Money: use Decimal with explicit currency minor-unit conversion/rounding, reject ambiguous/unsupported units or non-finite values; validate stock as bounded int. URLs are validated for storage/rendering only and **never fetched** by importer. Preview/validate/dry-run re-derive sanitized actions without product writes; persisted normalized snapshot digest is compared at execute. In one `DomainTransaction`, use a factored catalog validation/draft-create helper, create holding category once, generate fresh d-tags, write row outcomes and imported liabilities; no external calls, outbox intents, nested transactions or non-draft upserts. Duplicate upload returns prior import or deterministic no-op; conflicting source data on published/held/edited products is a conflict requiring new merchant review. Record fail-closed errors and atomic retry behavior.

### Task 3: Fail-closed activation gate, recategorization, API and Migration wizard

Implement an import-marker gate *in this wave*: any imported product with no verified cutover authorization remains draft and cannot become on-sale, be enqueued for publication (including bulk publish, patch and merchant-wide publish), or enter web/Gamma checkout. Check under the merchant/product transaction lock, not only in the UI; outbox rendering must also refuse accidentally queued blocked products. 04-02 will extend the same gate with snapshot/partition authorization. Add a merchant-owned action to reassign a still-draft imported product from holding category to a chosen live category; same transaction validates owner/category, does not auto-publish, rejects published/reserved products and preserves old IDs. Add guarded import upload/preview/validate/dry-run/execute/audit and preset endpoints via `@problem_boundary`, with ownership check on **each import ID**, CSRF and safe upload field handling. Admin nav Migration shows wizard, row errors, pending liabilities, signed import commitment (signature/id/pubkey + hashes), and an explicit warning: import is not a verified cutover.

### Task 4: Runtime tests + focused UI smoke

Fixture all three formats (30017/30018 + kind 5 ignored; nostrmarket export with order_items/invoice_id; multi-row Shopify CSV) and custom preset. Test non-USD conversion/rejection, malicious nested/oversize/secret fields, unsafe image URL, cross-merchant access, row errors, content-hash pinning, atomic repeat/parallel execute and source-ID collision across sources. Verify imported products have a holding category, `draft=true`, zero new outbox entries and cannot checkout, recategorization remains draft, bulk/patch/merchant-wide publication and both web/Gamma intake cannot bypass the import gate, no plaintext secrets in persisted/audit projections, signed commitment verifies. Run focused runtime tests and API/browser wizard smoke.
