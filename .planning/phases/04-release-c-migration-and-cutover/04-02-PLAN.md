## Phase Goal

Safely move a merchant's imported products from blocked drafts toward live stock only after old intake has stopped and every payable old invoice is either verified terminal or conservatively partitioned. Keep the safety boundary independent of whether the merchant reuses the old Nostr key.

<objective>
Build the evidence-backed cutover epoch, bounded same-instance nostrmarket/host wallet verification, durable partitions and settlement reconciliation, in-transaction stock/sellability checks, admin dashboard, and fail-closed abort. Remote/unverifiable sources remain previewable but cannot activate: a signed merchant upload alone cannot certify no missing invoices.
</objective>

### Task 1: m011 evidence/partition schema and fixed-source verification contract

Add epoch state, old-source identity, completeness/check timestamp, immutable signed snapshot hash, durable transitions/evidence (hashed invoice/order references; encrypt any reference needed for wallet queries) and `liability_partitions` with unique liability key, qty, held/consumed/released state. Build a **fixed trusted read-only same-instance adapter** (not a merchant-provided DB identifier): verify whole-extension disable and post-disable restart/quiescence, not only old merchant inactive state; enumerate all old orders/items and authorized legacy-tagged incoming wallet payments across every old source wallet; compare to uploaded snapshot by identity, item qty and invoice hash; verify wallet owner matches authenticated merchant; pin/verify the installed old extension's invoice-tagging/schema contract before treating tagged-payment enumeration as complete; bound pagination, reject missing/duplicate/unknown invoices, unavailable old extension, unowned wallets and inconsistent snapshots. If host cannot enumerate and attest complete scope, block activation and surface reason; other import formats remain blocked drafts until equivalent independently verifiable source support is planned. Define source cutoff and baseline physical count after freeze, accounting for paid orders prior to snapshot. Sign the *verified* manifest/epoch with the merchant's event signer and include source/cutoff/normalized hashes (signature is integrity evidence, not status evidence).

### Task 2: State machine + single-writer partition/reconciliation

Implement stage/freeze_request/verify_snapshot/reconcile/complete/abort as audited, merchant-scoped idempotent transactions, with CAS epoch/state tokens. Freeze_request instructs the operator to disable nostrmarket globally and restart the host, with explicit impact on other old merchants; it does **not** perform that action or claim merchant-inactive is sufficient; verify_snapshot performs the trusted checks and refuses stale/different source data. Wait keeps product blocked; partition uses a distinct row and the **same conditional capacity primitive** as `begin_saga`, plus product/merchant lock order, in one DomainTransaction. Fully accounted partitions allow sellable surplus, but never free their reserved units. Reconcile verified old payment: transition liability once; consume a partition and debit stock_on_hand/stock_reserved together, or when still blocked in wait mode debit stock_on_hand only, all exactly once with audit. Verified unpaid terminal: release any held qty only. Distinguish old stock decrement already reflected in starting baseline to avoid double consumption. Scheduled reconciler is leased, idempotent, paginated and fail-closed on status lookup errors; it also rechecks old-intake disabled state and snapshot freshness, marks the epoch blocked on reactivation/missing evidence, and conservatively blocks checkout/publishing when verification goes stale. Document the residual risk of an operator re-enabling the legacy system between checks. A merchant-requested 'cancel' records an external cancellation attempt but cannot mark resolved or release until authoritative unpaid terminality. Complete requires old source still disabled, the snapshot still matches, no unverified/uncovered payable liability, and retained holds for all payable partitioned liabilities. Abort hides/re-drafts imported products and retains payable holds; prohibit reactivating old intake from this extension.

### Task 3: Close every publication and intake escape + UI/API

Extend 04-01 import gate to require verified epoch and per-product fully covered/terminal liability, plus category review. Guard single-product edit/publish, bulk publish/visibility, merchant-wide republish, NIP-15/99 projections, stock changes, and outbox rendering; no queued intent should publicize blocked product/qty. At `begin_saga` lock merchant/product and recheck cutover and the fresh product draft/visibility/status/capacity *inside* the same transaction for both web and Gamma, before invoice creation; no admission based solely on `_resolve_items`' earlier read. Ensure new-product checkout remains unchanged. API under `@problem_boundary`: request freeze, verify snapshot, get status/evidence, choose wait/partition/terminal-reconcile, complete, abort; every ID owner-scoped and no free-form wallet or legacy DB input. Migration dashboard distinguishes import draft, old freeze unverified, uncovered liabilities, held-but-payable partitions, paid/terminal evidence, sellable surplus, complete and fail-closed abort; no destructive 'cancel invoice' claim.
