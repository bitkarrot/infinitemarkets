## Phase Goal

**As a** merchant mid-migration, **I want** to freeze sales on my imported
catalog, decide per pending legacy order whether to wait it out, cancel it,
or reserve its stock — and know imported stock can't sell until every
still-payable liability is resolved — **so that** the same unit is never
owed twice and I can still abort cleanly if something's wrong.

(Story source: LEG-04 + CONTEXT D-07..D-09.)

<objective>
Build the cutover state machine: `merchant_cutover` rows + transitions,
freeze scoped to legacy-marked products at the reservation choke point,
per-liability wait/partition/cancel resolution reusing `stock_reserved`
accounting, expiry-driven auto-resolution, the completion gate, the abort
path, and the Migration-tab cutover dashboard — proven by a runtime suite.

Purpose: this is the LEG-04 substance; 04-03 only has to *prove* it.

Output: `m00N+1_cutover`, `cutover.py`, intake choke, dashboard,
`test_cutover.py`.
</objective>

### Task 1: m00N+1_cutover schema + models

`merchant_cutover`: merchant_id UNIQUE, state, frozen_at, completed_at,
aborted_at, snapshot_json (liability counts at freeze). `liability_partitions`
(if not folding into inventory_reservations): id, liability_id FK,
product_id, qty, expires_at, state. Extend `imported_liabilities.state`
vocabulary to `open|resolved|partitioned|cancelled`. Cutover audit events
(reuse existing audit/activity table if present). Explicit migration list.

### Task 2: cutover.py — state machine + resolution

`freeze(merchant)` → `frozen`, snapshot open liabilities. `resolve(liability,
mode)` → wait: stays open w/ product blocked until `payable_until`;
partition: under DomainTransaction+for_update, `stock_reserved += qty`
(refuse if `stock_reserved + qty > stock_on_hand`), row state=partitioned,
hold row written; cancel: state=cancelled. `sweep()` → expire waits past
`payable_until` → resolved; expire partitions → release stock_reserved.
`complete(merchant)` → 409 while open liabilities exist; clears freeze.
`abort(merchant)` → release all holds, state=none (refused once completed).

### Task 3: Intake choke + API

In the reservation/checkout intake: if product carries the import marker (`import_id`) AND merchant
cutover is `frozen|reconciling` → refuse checkout with a clear
`cutover-pending` error (D-08: ALL imported products are held during
freeze; a product becomes sellable when every one of its liabilities is
`resolved|cancelled` — products whose liabilities are all resolved unblock
immediately, the rest unblock at `complete` or abort). API: freeze/unfreeze/complete POSTs,
`POST /liabilities/{id}/resolve`, `GET /merchants/{id}/cutover`.

### Task 4: Dashboard + test_cutover.py

Cutover dashboard in admin_migration.js: state badge, freeze/abort/complete
buttons, per-liability table with resolution picker (wait/partition/cancel),
qty sums, progress toward completion. Tests: transitions + audit, scoped
freeze (imported blocked, normal sells), each resolution path, partition
stock math + insufficient-stock refusal, expiry resolution, completion
gate, abort releases everything, cross-merchant denial.

</tasks>
