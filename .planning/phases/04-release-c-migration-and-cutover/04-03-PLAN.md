### Task 1: Export contract, CSV API/UI, round-trip tests

Define versioned stable header/encoding, explicit source currency, category, parent/variation ID, option labels/SKU, per-variant stock, visibility/draft and ordered image URL rows (including 20+ explicit overflow handling for inputs, never silently drop). Provide an authenticated, merchant-scoped streaming `GET /migration/products/export` or equivalent read-only admin download (CSRF protection applies to any mutating export-job creation, not to GET), with anti-formula escaping on attacker-controlled cells (`= + - @`, tab/CR etc), safe Content-Disposition filename, row bounds and no financial/order/key/buyer data. Add `Export products` beside import and support reimport of the native format as drafts without overwriting live products. Test SQLite/PostgreSQL, variants, multiple images, malicious cells, owner scope and export→reimport semantics. Export file is NOT a verified inventory/liability snapshot.

### Task 2: Optional owned-media ingest (stage 2)

Implement a bounded merchant-upload workflow for a manifest mapping only allowlisted imported CDN references to sha256/file names plus image bytes, with per-file ≤25 MB, per-merchant aggregate quota and small per-request batches (avoid a single 142 MB multipart request). Keep path segments server generated, reject traversal/symlinks, mismatched hash, spoofed MIME/non-image and cross-merchant references. Use a fixed merchant namespace under LNbits data/images, stage bytes securely, promote only on verified completion; retain CDN URLs until all selected images verify. Relink only authorized imported products in one audited DB transaction, with revision/outbox rules consistent with draft/publication state. The same verified file-upload primitive may accept a separately authorized brand-logo image (not an imported-product URL) for merchant settings. Retain source mapping and a recovery report, cover interrupted retries, duplicates, orphan cleanup and disk-full without destructive global cleanup. Use existing host static mount, not the extension code directory; Blossom remains an optional future destination only if its actual upload protocol/key custody is implemented and approved.

### Task 3: Merchant-operated brand match and UI review

Using screenshots (42 live product pages plus mobile/home/listing) and measured color/layout tokens, expose a per-merchant compact gallery toggle (4 desktop/2 mobile), hideable hero, logo-forward header and optional footer logo using managed uploaded media URL; optional fine-tuned charcoal/yellow tokens via existing contrast validation. Reuse current product variations/Lightning checkout and honest delivery/trust text: no Shopify payment buttons or remote fonts. Verify accessibility, alt text, 390px/1440px layout, image placeholder, footer and default theme regression; only this merchant enabling settings sees the brand match. No silent live-instance change or production config write without operator approval.
</tasks>
