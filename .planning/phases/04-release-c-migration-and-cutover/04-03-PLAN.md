### Task 1: Freeze-guard lifecycle rehearsal

Using a fixed-source nostrmarket fixture with an authorized merchant wallet and real service/API entrypoints, import stock=1 and one unpaid payable invoice for qty=1; verify old intake still active/missing order/unknown status each block snapshot. After disabling source and verifying complete invoice evidence, wait leaves the product blocked; partition holds the last unit; both web and Gamma order attempts cannot mint a new invoice or hold. In a separate product with stock=2 and one partition, a buyer may reserve only the remaining unit; another attempt fails. Exercise merchant review/recategorization/publish only after verification, and confirm stock projection is zero. Simulate verified old payment: consume hold and physical qty once; simulate verified unpaid terminality in a separate scenario: release hold, then new sale succeeds. Test duplicate paid notifications, late paid status after a claimed expiry, poll failure, abort retaining payable holds, covered vs uncovered completion, and normal native-product orders throughout.

### Task 2: Reachable concurrent allocation proof

Use two independent DB connections (not the single serialized test handle), product stock_on_hand=1 and the shared service-level conditional stock primitive. Coordinate simultaneous starts of legacy-partition and new-order allocation calls **before** opening write transactions; record entry and attempt outcomes without a barrier after either lock is held (SQLite BEGIN IMMEDIATE serializes writers). Prove both attempted the real allocation primitive, without claiming they executed the write at precisely the same instant. Assert exactly one allocation/hold wins, no stock constraint is violated, and a losing order cannot create a payable invoice. Because policy deliberately forbids checkout during unpartitioned freeze, do not claim this is a browser-level checkout race. Repeat under SQLite and PostgreSQL; include a targeted regression/mutation check demonstrating the test fails if the conditional capacity gate is removed. Avoid timing-only assertions and flaky scheduling.

### Task 3: Browser/API smoke, verification and docs

Browser smoke exercises the Migration wizard and admin cutover states, including holding category, unverified-source warning, source freeze confirmation, partitioned payable badge, and fail-closed abort notice. Verify route authorization, `make lint`, targeted SQLite + PostgreSQL runtime suites and repeated contention runs; record commands, results, tested topology and gaps in `04-VERIFICATION.md`. Update architecture overview/technical specification/README with schema, APIs, supported same-instance cutover verification, snapshot trust boundary, outstanding partitions, payment status reconciliation, how to recover from ambiguous source states and the still-blocked remote/Shopify cutover limitation. Only mark LEG-03/04/05 complete if their gates actually pass; milestone release/ship remains a separate decision.
</tasks>
