<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser→POST /media/upload | Untrusted multipart bytes + fields cross here; CSRF double-submit and cookie auth guard the route |
| pasted/dropped File objects | File content is sniffed server-side (magic bytes); client `accept` filter is convenience only — never relied on |
| gm-media-picker emit→parent state | Uploaded result.url/path is bound into theme/profile fields later PATCHed to the server — server validators remain authoritative |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-02-01 | Tampering | gmMediaUpload XHR | high | mitigate | X-CSRF-Token double-submit + same-origin credentials (existing security.py boundary); no Idempotency-Key per D-28 — upload dedup is content-addressed server-side |
| T-07-02-02 | Information disclosure | picker copy naming Blossom hostname | low | accept | Merchant's own configured server hostnames in their own admin UI — already shown in Settings → Merchant |
| T-07-02-03 | Elevation of privilege | usage/backend form fields | low | mitigate | Server validates both against MEDIA_USAGES/MEDIA_BACKENDS vocab and applies the media-origin gate — client sends exactly usage+backend+file, nothing else |
| T-07-SC | Tampering | npm/pip/cargo installs | high | accept | No package installs — component uses host-vendored Vue/Quasar globals only (RESEARCH audit: N/A) |
</threat_model>
